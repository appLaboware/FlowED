# Semantic Naming

Status: `INCUBATION / DOGFOODING`

## Purpose

Name a project only after its viability, boundary and residual are sufficiently established.

Core rule:

> THE NAME IS A CONSEQUENCE OF THE MODEL.

Do not generate branding first and invent architecture afterward.

## Inputs

- validated project boundary;
- technical category;
- invariant function;
- approved residual/adoption model;
- intended scope;
- commercial identity constraints when applicable;
- provider-neutral vs provider-specific boundaries.

## Process

```text
VALIDATED MODEL
  ↓
TECHNICAL CATEGORY
  ↓
INVARIANT FUNCTION
  ↓
SEMANTIC ROOTS
  ↓
NAMING STACK
  ↓
SMALL CANDIDATE SET
  ↓
SPOKEN / ENGINEERING / FAMILY TESTS
  ↓
COLLISION CHECK
  ↓
NAMING DECISION RECORD
```

## Naming layers

Keep separate when relevant:

- ecosystem / methodology;
- technical category;
- provider-neutral abstraction;
- commercial brand;
- provider implementation;
- repository/package/module name.

## Required output

A Naming Decision Record containing at least:

- chosen brand/name;
- formal product name;
- technical category;
- technical abstraction;
- semantic roots / etymology;
- why it fits;
- what it deliberately does not mean;
- provider family if applicable;
- repository naming proposal;
- domain candidate;
- organization candidate;
- one-line definition;
- short About text;
- rejected near-misses and reasons;
- validation status and remaining checks.

## Source lineage

Initial protocol basis: Semantic Naming Protocol supplied during FlowED project-genesis design. The tool must preserve the principle that architecture precedes naming and that user corrections are architectural evidence.
