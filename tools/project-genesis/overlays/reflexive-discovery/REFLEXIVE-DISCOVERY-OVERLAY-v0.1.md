# Reflexive Discovery Overlay v0.1

Status: `EXPERIMENTAL / UNVALIDATED`

## Purpose

This overlay applies when the object being investigated is also part of the mechanism, protocol, tool, research artifact, or process performing the investigation.

Generic case:

```text
IDEA I
  ↓
Project Genesis
  ↓
analysis of I
```

Reflexive case:

```text
IDEA / ARTIFACT I
  ↓
Project Genesis
  ↓
analysis of I
  ↓
result changes the instrument or protocol
  ↓
changed instrument may need to re-analyze I
```

The current `Project Genesis → Project Genesis` dogfood is the reference case, but this overlay is not restricted to Project Genesis.

## Why a separate overlay exists

Reflexive discovery introduces risks that do not exist, or are much weaker, in ordinary discovery:

- self-confirmation;
- circular evidence;
- protocol drift caused by one privileged case;
- overfitting to the self-case;
- hidden changes in the object while it is being assessed;
- invalid comparison between conclusions generated by different protocol versions;
- promotion of self-derived observations into generic rules without external validation.

These risks MUST NOT be forced into the generic protocol when they are specific to reflexive cases.

## Core law

> A self-derived conclusion does not become stronger merely because the instrument reproduces a conclusion that the instrument itself helped create.

## Required provenance classes

Every material claim or rule in a reflexive run SHOULD identify its origin as one or more of:

```text
EXTERNAL_EVIDENCE
INDEPENDENT_AGENT
HUMAN_ORIGINATOR
PREVIOUS_PROTOCOL
CURRENT_PROTOCOL
SELF_DERIVED
EXTERNAL_CASE
```

`SELF_DERIVED` is not invalid evidence, but it is not independent corroboration.

## Version separation

The following identifiers MUST remain distinct even when they refer to the same evolving project:

```text
OBJECT_VERSION
PROTOCOL_VERSION
EVIDENCE_SNAPSHOT
RESULT_VERSION
```

Example:

```text
Object: Project Genesis v0.1
Protocol: Discovery Protocol v0.1
Evidence Snapshot: E-2026-09-07-A
Result: R-001
```

If the result changes Project Genesis or the protocol, a subsequent assessment MUST NOT silently overwrite the previous state.

## Re-analysis trigger

A prior conclusion becomes a candidate for re-analysis when a protocol or object change could materially alter:

- factorization;
- evidence admissibility;
- sourcing classification;
- realization classification;
- exclusivity interpretation;
- residual factorization;
- confidence or coverage;
- stopping criteria.

This does not mean every change requires full restart. The protocol must identify the smallest affected dependency region.

## Anti-circularity rule

A reflexive argument of this form is insufficient:

```text
Protocol asserts R
  ↓
self-dogfood applies protocol
  ↓
self-dogfood observes R
  ↓
R is considered validated
```

Validation requires evidence that is not merely a consequence of assuming or encoding `R`.

## Promotion rule

> No rule discovered exclusively through self-dogfood may be promoted directly to the generic protocol.

Promotion path:

```text
SELF-DOGFOOD OBSERVATION
        ↓
REFLEXIVE-OVERLAY RULE / HYPOTHESIS
        ↓
EXTERNAL CASE(S)
        ↓
GENERALIZES?
   ├── NO  → remain overlay-specific
   └── YES → candidate for generic core
```

The number and diversity of external cases required for promotion are research questions and are not fixed in v0.1.

## Overfitting control

Every protocol change born from the self-case MUST answer:

1. What concrete failure or decisional gain triggered this rule?
2. Is the condition inherently reflexive?
3. Could the rule distort ordinary external cases?
4. What external case could falsify its generality?
5. Should the rule live in the core or only in this overlay?

Default decision under uncertainty: keep it in the overlay.

## Convergence tracking

A reflexive sequence may be represented as:

```text
I0 + Protocol0
  ↓
Result0
  ↓
I1 / Protocol1
  ↓
Result1
  ↓
...
```

The protocol MAY track whether successive iterations approach a stable region, but v0.1 does not define a validated convergence metric.

Candidate observables:

- change in factor tree;
- change in sourcing classifications;
- change in residual factorization;
- number of previously accepted claims reopened;
- number of protocol rules added/removed;
- number of conclusions surviving protocol-version change.

No convergence claim is authorized without a defined metric and stopping rule.

## Relation to dogfooding

Ordinary dogfooding means using one's own product in real work. Reflexive discovery is narrower and stronger: the product or method is used on a case that can change the very method used to inspect it.

Therefore:

```text
DOGFOODING
  ⊃
REFLEXIVE DISCOVERY
```

Not every dogfood is reflexive discovery.

## Current reference case

```text
Project Genesis
  ↓
Project Genesis analyzes Project Genesis
  ↓
findings modify Project Genesis protocol/tool boundaries
  ↓
modified Project Genesis re-evaluates affected conclusions
```

This case MUST remain explicitly marked as a reflexive case and MUST NOT be treated as sufficient evidence of generic validity.

## Candidate research questions

- **RQ-RD1:** How can independent evidence be distinguished from self-derived evidence in a discovery process where the artifact and the investigation instrument partially overlap?
- **RQ-RD2:** Which protocol changes require re-analysis of earlier conclusions, and how can the smallest affected dependency region be identified?
- **RQ-RD3:** Can a reflexive discovery process converge toward a stable factorization and sourcing profile under reproducible stopping criteria?
- **RQ-RD4:** How can self-confirmation and circular validation be detected or bounded?
- **RQ-RD5:** How can overfitting to the self-case be measured before promoting rules to the generic protocol?
- **RQ-RD6:** Which rules discovered through reflexive self-dogfood generalize to external projects?

## Current maturity

This overlay is a working methodological artifact born from the Project Genesis self-dogfood.

It is not scientifically validated and does not claim novelty.

Its immediate function is operational: prevent the self-case from silently contaminating the generic protocol while preserving the unusually rich feedback that self-application produces.
