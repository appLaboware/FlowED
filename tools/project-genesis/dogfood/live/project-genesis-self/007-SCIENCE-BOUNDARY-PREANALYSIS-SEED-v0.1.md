## 1. What has already been satisfied

The conversation and prior dogfood provide enough material to treat Phase 01 — protected understanding — as provisionally satisfied for the purpose of launching an external scientific-boundary pre-analysis.

This is NOT a final homologation of the idea. It means only that the originator's intent is sufficiently explicit to support a first independent investigation without forcing the consultants to invent the idea for us.

Core understood intent:

> Project Genesis is a protocol/toolchain for taking an early project idea through faithful understanding, evidence confrontation, factorization only as far as decisionally necessary, discovery of existing solutions and prior art, reuse/sourcing/composition analysis, preservation of idea evolution and provenance, human decision support, and later project identity/materialization — while preventing premature judgment, false novelty claims and unnecessary proprietary construction.

The current scientific candidate around PMFN is narrower:

> Seek the coarsest factorization that is still sufficient for stable, auditable, evidence-supported decisions about sourcing, transformation, composition, differentiation, risk and uncertainty, without destroying relevant architectural relations.

The current reflexive use case is special and governed by an overlay: `Project Genesis → Project Genesis`.

## 3. Why science-boundary pre-analysis is the next step

The protocol must not ask `is this new?` before asking `what is already known?`.

The purpose of the next phase is therefore NOT to prove novelty and NOT to recommend whether to continue.

It is to construct the strongest possible boundary between:

```text
ESTABLISHED KNOWLEDGE
EMPIRICALLY SUPPORTED PRACTICE
KNOWN METHODS / FORMALIZATIONS
KNOWN IMPLEMENTATIONS
ADJACENT / PARTIAL PRIOR ART
CONTESTED OR WEAKLY SUPPORTED CLAIMS
UNRESOLVED QUESTIONS
NOT YET FOUND UNDER THE SEARCH SCOPE
```

## 4. Scientific-boundary dimensions

Consultants must investigate independently at least:

### 4.1 Conceptual boundary

- early idea elicitation and semantic fidelity;
- premature evaluation and creativity/innovation bias;
- idea evaluation as development rather than only gatekeeping;
- problem framing and reframing;
- self-application / reflexive practice / dogfooding / self-hosting where relevant;
- software reuse;
- component sourcing / make-buy-reuse decisions;
- architectural innovation and composition;
- requirements decomposition / problem decomposition / stopping criteria;
- evidence-based software engineering;
- decision engineering under uncertainty;
- provenance, confidence, counterevidence and reproducibility.

### 4.2 Method boundary

Look for protocols, models, algorithms, taxonomies, systematic review procedures, decomposition criteria, stopping rules, sourcing frameworks, decision matrices, evidence grading systems, innovation measurement frameworks and related instruments.

### 4.3 Application boundary

Find actual software, services, OSS tools, commercial tools, institutional workflows and reference implementations that operationalize any part of the intended Project Genesis behavior.

The consultant must distinguish an academic concept from an executable implementation.

## 5. Prohibited conclusions in this phase

Do not conclude:

- GO / NO-GO;
- good idea / bad idea;
- commercially viable / commercially unviable;
- patentable / non-patentable;
- world-first / globally novel;
- build / don't build;
- product name;
- final architecture.

The consultant is mapping the boundary of available knowledge, not deciding what the originator should want.

## 6. Required result classification

For each identified concept, method or implementation, classify:

```text
KNOWN_ESTABLISHED
KNOWN_PARTIAL
ADJACENT
CONFLICTING_EVIDENCE
UNRESOLVED
NOT_FOUND_IN_SCOPE
```

Evidence state must be independent:

```text
DISCOVERED
IDENTITY_VERIFIED
CLAIM_VERIFIED
CONTRADICTED
UNRESOLVED
```

`NOT_FOUND_IN_SCOPE` must never be rewritten as `DOES_NOT_EXIST`.

## 7. Required science-boundary output

Each consultant must return:

1. EXECUTIVE BOUNDARY SUMMARY
2. SEARCH STRATEGY
3. SEARCH SCOPE AND LIMITATIONS
4. CONCEPTUAL PRIOR-ART MAP
5. METHOD / FORMALIZATION MAP
6. APPLICATION / IMPLEMENTATION MAP
7. CLOSEST ANTECEDENTS
8. WHAT PROJECT GENESIS CLEARLY MUST ADOPT RATHER THAN CLAIM
9. WHAT APPEARS ONLY PARTIALLY COVERED
10. POSSIBLE RESIDUAL QUESTIONS — explicitly non-novelty claims
11. COUNTEREVIDENCE / ANTITHESES
12. OPEN SCIENTIFIC QUESTIONS
13. SOURCE TABLE with canonical links/DOIs
14. CLAIM → EVIDENCE → COUNTEREVIDENCE → UNCERTAINTY trace
15. CONFIDENCE / COVERAGE commentary
16. RECOMMENDED NEXT SEARCHES
17. FINAL STATE: `BOUNDARY_INSUFFICIENT | BOUNDARY_PARTIAL | BOUNDARY_READY_FOR_CONSOLIDATION`

## 8. Multi-consultant rule

Consultants work independently.

Do not provide them with one another's conclusions.

We do not use majority voting.

Disagreement is evidence that must be investigated.

The consolidation step will identify:

```text
CONSENSUS
DIVERGENCE
SOURCE QUALITY DIFFERENCES
SEARCH-SCOPE DIFFERENCES
SEMANTIC DIFFERENCES
UNRESOLVED COLLISIONS
```

## 9. What happens after the reports return

The reports are consolidated into one `SCIENCE-BOUNDARY-RECORD`.

Only then do we ask:

> Given what science and practice already establish, what remains necessary to reach the human's desired endpoint?

That downstream phase may produce adoption, composition, adaptation or residual research/build work.

Commercial viability remains explicitly downstream.

## 10. Dogfood requirement

Because Project Genesis is analyzing Project Genesis, the reflexive overlay applies.

Self-derived conclusions must not be counted as independent corroboration.

Any rule discovered only in this self-case remains overlay-specific until tested externally.
