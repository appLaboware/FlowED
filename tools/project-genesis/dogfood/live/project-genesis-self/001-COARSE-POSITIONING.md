# Run 001 — Coarse Positioning of Project Genesis

Status: `ACTIVE / PARTIAL EVIDENCE`
Date: 2026-09-07
Subject: `Project Genesis` analyzed by `Project Genesis`

## 1. Input

Raw proposition:

> A system that receives an early project/business/software idea, progressively structures and confronts it with available evidence, identifies what already exists and what can be reused/transformed/composed, preserves the evolution of the idea, optionally supports human pre-consultation, and after sufficient clarification can continue into naming, identity, repository design, repository materialization and AI-ready project continuation.

## 2. Question of this run

Can `Project Genesis` be evaluated as one indivisible sourcing unit, or does the first evidence scan show that further factorization is decisionally necessary?

This run does NOT attempt to produce final pertinence, exclusivity or residual-factorization values.

## 3. Initial coarse hypothesis

```text
Project Genesis
    = evidence-informed idea positioning
    + guided evolution
    + project genesis / materialization
```

If one existing admissible product covers this complete unit sufficiently, further proprietary decomposition may be unnecessary.

If different parts are covered by different classes of existing solutions, further factorization has material decisional value.

## 4. Exploratory candidate universe — first pass

This is an exploratory evidence set, not a systematic review and not evidence of search saturation.

### 4.1 AI idea validation / evidence-positioning products

#### ValidateIdea

Observed positioning:
- market and competitor analysis;
- explicitly says `No predictions. No scoring.`;
- source-linked market/competitive research intended to help the human decide.

Evidence:
- https://validateidea.ai/

Initial relevance:
- strong overlap with neutral evidence positioning;
- important counterexample to any claim that `no-score, sourced idea analysis` is unique.

#### Preuve AI

Observed positioning:
- scans many live data sources;
- competitor mapping;
- viability scoring;
- founder-market fit;
- market sizing;
- sourced claims;
- pivot recommendations.

Evidence:
- https://preuve.ai/

Initial relevance:
- strong overlap with evidence collection, competitor discovery and startup analysis;
- differs from Project Genesis' current neutrality objective because it advertises a viability score / verdict.

#### Verdiccio

Observed positioning:
- evidence analysis across demand, competition, monetization, GTM and risk;
- searches multiple external evidence sources;
- produces dimension scores and an overall verdict.

Evidence:
- https://www.verdiccio.com/

Initial relevance:
- significant overlap with evidence gathering and structured analysis;
- again shows scoring/verdict orientation rather than neutral position-only semantics.

#### IdeaEval / IdeaProof / IdeaValidator / Foundable and similar tools

Observed pattern:
- structured startup/business idea analysis;
- market and competitor discovery;

Evidence examples:

Initial relevance:
- the broad category `AI idea validation` is already crowded;
- Project Genesis must not claim novelty merely from structured AI analysis of an idea.

## 5. Observation

No single candidate in this first pass has yet been shown to cover the entire coarse Project Genesis proposition.

However, the evidence already shows that distinct regions of the proposition are covered by different mature product/tool classes:

```text
idea evidence / market positioning
    → many AI validators / research products

idea → structured software plan
    → Scaffold / Sago / GitHub Copilot and others

blueprint → repository
    → Backstage Scaffolder / starter-repo generators / template ecosystems
```

This means treating Project Genesis as one indivisible sourcing unit hides materially different sourcing decisions.

## 6. PMFN decisional effect

### Split candidate

```text
Project Genesis
├── A. Evidence Positioning & Discovery
├── B. Project Modeling / Evolution Continuity
└── C. Project Materialization / AI-ready Handoff
```

### ΔD(split)

Qualitative status: `HIGH / MATERIAL`.

Reason:

The split changes:
- candidate universe;
- likely realization strategy;
- adoption/composition opportunities;
- ownership boundary;
- potential residual;
- likely exclusivity interpretation.

Therefore PMFN says: **continue factorization**.

No numeric `ΔD` is assigned because the protocol has not yet defined or validated a scale.

## 9. Implementation evidence discovered by this run

This use of Project Genesis against itself reveals that the tool/protocol needs at least the following behaviors:

### IR-001 — Coarse-first analysis

The runtime must allow an assessment to begin without a predefined exhaustive capability tree.

### IR-002 — Candidate universe by factor

Evidence candidates must be attachable to the exact factor they cover; otherwise broad competitors create false whole-product equivalence.

### IR-003 — Partial coverage semantics

The evidence model must distinguish:
- whole-equivalent candidate;
- partial-factor candidate;
- component/provider;
- pattern/standard;
- adjacent solution.

### IR-004 — Split rationale

Every factor split should carry a machine-readable/human-readable reason explaining what decision changed because of the split.

### IR-005 — No false numerical precision

The runtime must permit `UNKNOWN`, qualitative states and incomplete profiles before scoring models are validated.

### IR-006 — Evidence snapshot

Every run needs date, source set and protocol version so later reruns can explain why a project position changed.

### IR-007 — Dogfood-as-example

A completed dogfood run should be renderable directly as user documentation/example without rewriting its conclusions into a separate tutorial.
