# Project Genesis — Self-Dogfood Assessment Seed

Status: `DOGFOOD / UNVALIDATED`

## Raw idea

Create a tool/system that receives an early idea and progressively produces an evidence-informed position, a realization/reuse profile, project identity, repository design and AI-ready project materialization.

## PMFN objective

Use Project Genesis against itself before expanding implementation.

The assessment must determine:

1. which parts already exist as products, protocols, standards, OSS or services;
2. which parts can be configured or extended;
3. which parts can be composed;
4. which parts require adaptation;
5. which residual actually deserves proprietary implementation;
6. where differentiation is conceptual, architectural or executional;
7. how strong the evidence is for every conclusion.

## Mandatory adversarial questions

For every factor above:

- Is there an admissible existing product that already performs this function?
- Is there an open-source implementation?
- Is there a standard or protocol that should be adopted instead of recreated?
- Can the capability be supplied by an API/provider?
- Can multiple existing components be composed without owning the implementation?
- Does the proposed factor belong inside Project Genesis or under another sovereign domain?
- Is the factor needed for the minimal product or only for future institutional use?

## Hypotheses to try to falsify

- H-PG1: an integrated evidence-to-project continuity is insufficiently covered by existing products.
- H-PG2: most individual capabilities can be adopted from existing products or libraries.
- H-PG3: the potential proprietary residual is primarily orchestration, provenance continuity and decision genealogy rather than commodity functions.
- H-PG4: institutional pre-consultation is a viable projection of the same evidence model without changing the core protocol.
- H-PG5: repository creation is only one downstream materialization target and must not define the product boundary.

## Dogfood success criterion

Dogfood succeeds even if the conclusion is that Project Genesis should contain little or no proprietary code.

> **The tool is rewarded for preventing unnecessary construction, including its own.**

## Next execution

Run a systematic candidate-universe search for each factor, record candidates and evidence, then refine the factorization only while further splits materially change realization, sourcing, exclusivity, risk or confidence decisions.
