# R1-P01 — Porter native surface

Purpose: prove native Porter capabilities before writing any new orchestration layer.

Porter baseline: v1.6.1.

This experiment covers:

- named configuration contexts;
- parameter sets;
- credential sets;
- credential injection without persisting resolved secrets;
- install;
- upgrade;
- uninstall;
- bundle outputs;
- sensitive outputs via filesystem secret plugin in lab only;
- custom stateless action;
- explain/lint/inspect;
- OCI publication to a local registry;
- bundle archive;
- Porter MCP read-only surface;
- Porter MCP explicit write opt-in;
- MCP install/invoke/uninstall;
- MCP masking/blocking of sensitive outputs.

This experiment intentionally uses the exec mixin only as a controlled probe of Porter
itself, not as a recommendation for application deployment. Porter documents exec as
the mixin of last resort.

Acceptance evidence is generated by GitHub Actions and written to RESULTS.md after
a successful run.
