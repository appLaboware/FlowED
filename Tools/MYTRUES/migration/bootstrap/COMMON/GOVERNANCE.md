# Governance

## Decision authority

Canonical project decisions require explicit authority.

Automated tools and LLMs may:

- inspect;
- propose;
- summarize;
- generate candidate changes;
- produce evidence.

They do not gain canonical authority merely by producing an output.

## Change classes

- normative protocol/specification;
- reference implementation;
- research hypothesis;
- experiment/evidence;
- documentation/projection;
- commercial/private extension.

A change must declare its class when ambiguity would affect authority.

## Adopt-first principle

ADOPT -> PERSONALIZE/ADAPT -> COMPOSE -> FORK -> INVENT

New mechanisms should be invented only after relevant prior art and adopted
alternatives have been exhausted sufficiently for the decision at hand.

## Historical integrity

Superseded decisions and research branches are preserved rather than silently
rewritten.

Current state and historical state must remain distinguishable.
