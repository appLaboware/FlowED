# FlowDisP Research Profiles

## PRODUCT

Use for claims about a product or capability existing in practice.

Search classes can include commercial products, open-source repositories, public prototypes, plugins/extensions, archived projects, package registries, vendor docs, release notes, public demos, and papers with executable artifacts.

A public prototype can refute **capability novelty** if the capability is actually present. It does not prove production fitness, commercial equivalence, supportability or adoption suitability.

The ABR may inspect code only to confirm capability/mechanism existence.

Typical dimensions: `CAPABILITY`, `IMPLEMENTATION`, `PRODUCTIZATION`, `COMMERCIAL_OFFERING`, `ARCHITECTURE`.

## ACADEMIC

Use for concepts, principles, models, taxonomies, methods or theoretical claims.

Search classes can include peer-reviewed papers, conference proceedings, books/chapters in relevant scholarly traditions, standards/specifications, materially relevant theses/dissertations, primary historical sources, systematic reviews/mappings for navigation, and citation chains.

Rules:

- same meaning with different terminology counts as an antecedent;
- same name with different meaning does not;
- reviews help navigation but strong claims should return to primary sources when feasible;
- “first” requires much stronger evidence than “we did not find”.

Typical dimensions: `CONCEPT`, `METHOD`, `COMPOSITION`, `THEORETICAL_RELATION`, `TERMINOLOGY`.

## METHOD

Use for protocols, standards, workflows, governance rules or decision methods.

Compare purpose, decision rule, inputs, outputs, stopping criteria, authority and evidence requirements across standards, RFCs/specs, industry methods, process frameworks, public operating playbooks and academic methods.

## ARCHITECTURE

Use for claims about structural mechanisms or system organization.

Search architectural patterns, reference architectures, systems papers, open-source systems, vendor architectures, standards, protocol stacks and framework internals when relevant.

Functional similarity alone does not prove architectural equivalence; essential structural properties must be stated.

## Multiple profiles

A case may require more than one profile, but independent claims should become separate cases rather than one unbounded “research everything” task.
